> 推荐这篇文章，Anthropic 系统性地定义了"上下文工程"这个新概念。它回答了比"怎么写更好的 prompt"更根本的问题：在 LLM 注意力预算有限的前提下，什么样的上下文配置最容易触发你想要的行为。如果你在设计和维护 Agent 系统，这篇里的 compaction、渐进式检索、工具设计原则是基本功。
>
> 上下文工程：比 Prompt 工程更重要的 Agent 设计能力
>
> Prompt 工程关注怎么写好指令。上下文工程回答一个更广的问题：在 LLM 的有限注意力预算下，什么配置的 token 最有可能产生期望的行为。
>
> 核心洞察：LLM 跟人类一样，有一个注意力预算。每个新 token 消耗一部分预算。上下文必须被视为有限资源，具有递减的边际回报。这不是软约束——是 transformer 架构的 n² 注意力关系导致的硬约束。
>
> 各层的最佳实践
>
> 系统提示应该极其清晰，用简单直接的语言，达到正确的高度——在"硬编码脆弱的 if-else 逻辑"和"过于模糊的指导"之间。curate 最小但足够的信息集，然后根据失败模式迭代添加。
>
> 工具设计上，Agent 应该定义清晰、自包含、对错误鲁棒。最常犯的错误是工具太多——如果人类工程师没法确定某个场景该用哪个工具，AI Agent 也做不到。
>
> 示例仍然是最好的实践，但不要塞一堆边缘情况。选一组多样化、规范化的例子。对 LLM 来说，示例是千言万语的图片。
>
> 长期任务的三个技巧
>
> 压缩。把接近窗口限制的对话总结成高保真摘要，开启新窗口。关键在保留什么 vs 丢弃什么。先最大化召回率、再提高精确度。
>
> 结构化笔记。Agent 定期把笔记写入上下文之外的持久存储。Claude 玩宝可梦演示了这个模式：在成千上万步游戏操作中，Agent 精确追踪进度，不用把所有信息都存在上下文里。
>
> 子 Agent 架构。一个主 Agent 协调 plan，多个专门子 Agent 各自在干净的上下文中处理深度任务。每个子 Agent 可能用上万 token，但只返回 1000-2000 token 的精炼摘要。
>
